RESULTS BOARD ONE DGX SPARK

Quality first.
Then the ranking.

Our own tests of LLM inference recipes on a single DGX Spark. Passing recipes will be ranked by the useful work they deliver within a declared latency budget. Failed and inconclusive evaluations will be published separately, so every verified test contributes evidence.

OUR PUBLICATION RULE

We publish recipes we have run and verified ourselves, with the evidence needed to inspect the result. Every entry must identify its reference, recipe, environment, and benchmark versions, quality decision, and measured performance. The engine is one component of the recipe, alongside model artifacts, deployed precision, build and launch settings, cache policy, and decoding.

Failed

Evidence establishes a regression beyond the declared margin, or a critical correctness gate fails. Each entry will identify the failed gate, affected workload, and supporting measurements.

Inconclusive

The evidence does not establish a pass or a failure under the declared rules. Each entry will explain the uncertainty or missing evidence and what would be needed to resolve it. Inconclusive does not mean the recipe is defective.

HOW TO READ THE BOARD

A rank has a scope.

Compare matching workloads

Rankings apply within the same model and checkpoint, task suite, context and load profile, and latency limits. Each record will identify the recipe’s artifacts and deployed precision, engine/version, build and launch settings, KV precision, memory use, and actual batching where available.

Qualify before ranking

Only recipes that pass the declared quality and serving-correctness gates qualify for ranking. Failures and inconclusive decisions will remain visible with their evidence. Preservation must be established against the original-precision reference; a missing reference leaves that claim unmeasured.

Count useful work

Goodput is correct, valid responses meeting the declared service-level objective per second. We will also report aggregate output tok/s, per-stream ms/token, TTFT, and end-to-end latency for the same versioned workload profile. Goodput is scored from the actual responses under load, not inferred from a separate accuracy run.

Inspect the evidence

Each entry will link to all four versioned records, the actual driver version, a runnable benchmark package with data acquisition and setup instructions, pinned scoring and analysis scripts, paired outcomes, confidence bounds, timing records, errors, and evaluation duration. Any external figures used for context will be labeled reported and excluded from our rankings.
